# 小院天气：双端统一界面设计提案

日期：2026-10-26。状态：设计待用户确认，尚未实现本次改版。

## 产品基准

iOS、Android 均使用同一套 Godot 小院场景和业务脚本。保留现有院落、阿晴、大肥鱼及互动资源。系统定位、更新渠道、安全区属于平台适配。

现有 Godot iOS 213 的分发修复独立于本次界面改版，不作为改版交付。

## 页面与功能归位

| 入口 | 内容 | 退出与状态 |
| --- | --- | --- |
| 小院主屏 | 城市、当前天气、体感、必要天气数据、更新时间、简短日期主题；院落及双角色为视觉主体 | 定位中、手动城市、定位失败、缓存过期、天气失败明确可辨；不把示例天气当实时天气 |
| 点城市 | 自动定位与已有城市选择 | 底部面板；取消不改城市；定位失败保留当前城市并提供重试 |
| 陪一会儿 | 摸头、招呼、热饮、休息四个常用动作；角色也可直接点击互动 | 半高模态底部面板；关闭按钮、遮罩、返回键关闭；动作成功后由真实角色响应写入日记 |
| 小院手记 | 日记 / 纪念日两个分段；当天节气、节日及活动作为记录上下文 | 独立页面返回小院；纪念日编辑时保存、丢弃、继续编辑保护草稿 |
| 小院设置 | 邻居开关、动态效果、安静观赏、场景探索、应用更新、许可来源 | 独立页面；城市不在设置中重复展示 |
| 场景探索 | 天气与节日体验、动作与特效预览 | 进入后持续显示“体验场景”；单一“回到今天”退出；预览不写入真实陪伴记录、不消耗真实日间/夜间事件 |

首页不再把“天气”按钮指向天气模拟菜单。删除日历、陪伴中重复的图鉴入口，统一归入场景探索。首页两项常用操作替代按钮堆积。

## 方案取舍

推荐：保留沉浸式小院，两个常用操作，低频内容逐层收纳。角色与天气仍是主体验。

备选：三页底部导航（小院、手记、探索），入口更直接，但常驻导航占据院落画面；适合探索内容成为高频任务后再考虑。

不采用：仪表盘卡片首页。会削弱院落与角色陪伴的连续感。

## 特效接入与验收

现状静态证据：213 PCK 中有 200 个组合、20 类图形、366 天日常与 74 条节日配置，全部组合存在配置引用。不是 200 段独立动画；配置引用不等于运行可见。

| 特效类别 | 场景触发 | 表现与退出 | 实际验收 |
| --- | --- | --- | --- |
| 雨雪、雾、风叶 | 真实天气状态 | 跟随天气变化渐入/退出；不遮挡天气文字与角色脸部 | 天气信号到渲染完整链路，轻雨/暴雨/雪/风/雾分别录屏 |
| 爱心、热饮蒸汽 | 摸头、回应、双方喝热饮 | 短暂出现；动作完成退场；拒绝重复点击造成无限堆叠 | 双角色动作、道具与粒子的时序一致，日记只记录成功事件 |
| 季节氛围 | 日期、当地时段、实际天气 | 少量、局部；与天气冲突时让位；不用全年随机轮播代替场景适配 | 每季、白天/夜间、雨雪对照录屏 |
| 灯笼、花瓣、庆祝 | 真实节日或个人纪念日 | 有语义、有限演出时段；不持续满屏循环 | 日期进入、跨日退出、同日多事件冲突、预览恢复 |
| 安静纪念 | 哀思类日期或个人设定 | 静态烛光或柔和局部表现，停止欢庆粒子 | 与生日叠加时仍保持安静，不触发欢庆动作 |
| 图鉴中的组合变体 | 用户明确预览 | 标注示例，不改变城市、真实天气与真实事件次数 | 所有保留入口都能触发可见效果；无可见区别的变体合并而非凑数量 |

优先级：必要天气表达、用户即时互动、日期活动、环境装饰。夜间、低电量、慢帧和减少动态有明确降级；必要状态反馈保留。最终数量以可解释、可观察的有效效果为准。

## 视觉与交互契约

沿用原画、奶油色面板、青绿色操作色；不更换角色。天气数字稳定，状态文字有对比度，触控热区独立于图标尺寸。适配 iPhone 安全区与 Android 返回键。

面板保留院落上下文，模态打开时阻止背景点击，关闭后焦点回到入口。安静观赏必须有持续可见的退出方式。动画遵循系统减少动态偏好与应用设定。

设计图中的天气、时间、日记均为示例数据。静态设计图不证明动画接入或平台验收；按图实现后需双端实际录屏检查。
